## Secure Channel Repair

Potential capabilities:

* Detect domain membership
* Test the machine trust relationship
* Identify the current domain and preferred domain controller
* Validate DNS before attempting repair
* Check time synchronization and Kerberos prerequisites
* Test connectivity to required domain services
* Detect whether the local machine password or secure channel is broken
* Attempt safe repair using supported Windows methods
* Support alternate credentials without exposing them
* Re-test the secure channel after repair
* Distinguish DNS, firewall, time, replication, credential, and trust failures
* Avoid removing and rejoining the domain unless explicitly approved and no safer repair works

## Disk Health Audit

* Storage Spaces status

## Windows Update Health

* Windows Update service status and startup configuration
* BITS, Cryptographic Services, and related dependencies
* Pending reboot detection
* Installed update history
* Recent failed updates
* WSUS, Microsoft Update, Intune, or policy source detection
* Windows Update policy conflicts
* Update cache health
* Delivery Optimization state

## Event Log Summarizer

Potential capabilities:

* Configurable time range
* Local or remote computer support
* Relevant administrative logs
* Group repeated events by provider, event ID, message pattern, and likely root cause
* Suppress known noise without hiding important failures
* Correlate events across System, Application, security-related, servicing, update, Hyper-V, DNS, DHCP, Active Directory, storage, and networking logs
* Rank issues by severity, frequency, recency, and probable operational impact
* Produce both a concise summary and detailed evidence
* Preserve timestamps, event IDs, providers, and source logs
* Avoid pretending that correlation proves causation
* Export machine-readable and human-readable reports

## Firewall Rule Tester

Treat this as a focused feature, not merely a port scanner.

Potential capabilities:

* Accept source, destination, protocol, port, and direction
* Test local Windows Firewall rules
* Identify matching allow and block rules
* Evaluate profile applicability: Domain, Private, and Public
* Evaluate enabled state, direction, protocol, port, program, service, interface type, remote address, and local address
* Detect explicit block rules that override expected access
* Show whether the failure appears local, remote, routing-related, DNS-related, service-related, or upstream
* Check whether the target service is actually listening
* Test TCP and UDP appropriately without claiming UDP success from the absence of an error
* Support remote Windows hosts where permissions allow
* Compare configured rules with observed connectivity
* Explain which rule likely allowed or blocked traffic
* Include Windows Firewall logging status and relevant dropped-packet evidence
* Support read-only testing by default
* Require explicit approval before creating, changing, enabling, or deleting firewall rules
* Log before-and-after state for any approved rule modification
* Never create broad “Any/Any” rules as an automatic fix
